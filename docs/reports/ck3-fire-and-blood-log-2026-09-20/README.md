## Что означает ссылка на `fab_aurion`

В оригинале Fire and Blood:

- `common/dna_data/00_fab_sotd_dna.txt:393` определяет внешность `fab_aurion`.
- `history/characters/00_fab_sotd_canon_children_dummies.txt:21` определяет служебного персонажа `Dummy_fab_aurion` для внешности будущего ребёнка.
- `common/scripted_effects/00_fab_sotd_canon_children.txt:206` передаёт `ID = fab_aurion` в проверку беременности AGOT, а строка 212 — `FINAL_CHILD_ID = fab_aurion` в обработку жизненного цикла.

Базовый `agot_canon_children_had_child_trigger` в `common/scripted_triggers/00_agot_canon_children_triggers.txt:190` содержит `exists = character:$ID$`. После подстановки получается обращение к отсутствующей исторической записи `character:fab_aurion`. Вызовы проходят через общую проверку беременности и жизненного цикла. Лог не указывает точный развёрнутый вызов каждой из двух записей; соответствие механизму установлено по коду.

Это **не отсутствие DNA и не ошибка перевода**. Проверка также умеет находить уже рождённого ребёнка по флагу и глобальному списку; сообщения сами по себе не доказывают, что рождение полностью сломано. Для устранения нужна адаптация проверок для этого добавленного ребёнка. Просто подставить `Dummy_fab_aurion` нельзя: существование служебного образца не означает, что сюжетный ребёнок уже родился.

Проверенные определения и происхождение файлов: [definition-evidence.json](definition-evidence.json).

## Маркер Молчаливых Сестёр

`events/agot_events/agot_silent_sisters_events.txt:258` проверяет:

```text
NOT = { has_character_flag = fab_never_silent_sister }
```

Единственное найденное активное обращение — эта проверка. Следовательно, именно предусмотренное этим флагом исключение сейчас не включается. Это не отменяет другие ограничения события: рядом отдельно проверяются `canon_status_canon`, вдовство, пол, религия и брак. Кому автор собирался выдавать дополнительную защиту, из данного обращения установить нельзя.

## «Неиспользуемое» не всегда следует удалять

Особенно показателен `fab_north_slain_dragon`:

- В `events/aegons_conquest/fab_ac_05_north.txt:226`, `233`, `240` записывается один из трёх драконов.
- На строке 600 эта переменная используется как персонаж правого портрета события `fab_ac_north.0012`.
- Английская локализация обращается к `[global_var:fab_north_slain_dragon.GetName]`; наша русская версия сохраняет эту подстановку (`localization/russian/ac/fab_ac_05_north_l_russian.yml:39`).

Удаление присваиваний повредило бы имя и портрет погибшего дракона. **Это подтверждённое исключение из диагностики, а не кандидат на очистку.** Движок сам предупреждает в сообщении, что обращения из локализации не учитываются.

У остальных 25 имён поиск в оригинале Fire and Blood нашёл присваивания, но не чтение. Это прежде всего кандидаты на отдельный разбор авторского намерения; по одному предупреждению нельзя заключить, что требуется удаление или добавление условий. В этой группе есть как глобальные переменные, так и `add_character_flag`, хотя движок объединяет их под названием `Variable`.

Символьные значения рассматриваются отдельно:

- `hold`: записывается в `fab_ac_landing_plan`, `events/aegons_conquest/fab_ac_01_landing.txt:694`.
- `pact`: записывается в `fab_ourfury_route`, `common/scripted_effects/03_fab_ourfury_effects.txt:41`.
- `shivers`: `events/sons_of_the_dragon/agot_sotd_shivers_events.txt:282` вызывает `contract_disease_notify_effect = { DISEASE = shivers }`. Общий эффект AGOT (`common/scripted_effects/20_health_effects.txt:633`) записывает `flag:$DISEASE$`, однако ветки для `shivers` в нём нет. Поэтому этот вызов не выбирает уведомление о болезни. Сам признак болезни добавляется непосредственно перед вызовом; предупреждение не означает отсутствия самой болезни.
