## Что означает CREATOR

Это **отсутствующий обязательный аргумент функции**, а не неизвестный ID персонажа и не ошибка написания существующего имени. В рассматриваемых вызовах вообще нет строки `CREATOR = ...`.

Фактический пример из AGOT+:

```text
agot_create_artifact_aenys_crown_effect = { OWNER = this }
```

Современная функция AGOT содержит два подстановочных параметра:

```text
$OWNER$ = { save_scope_as = owner }
$CREATOR$ = { save_scope_as = creator }
...
create_artifact = {
    ...
    creator = scope:creator
}
```

`OWNER` обозначает владельца, `CREATOR` — персонажа, которого запишут изготовителем артефакта. При разворачивании такого вызова не хватает второго аргумента, поэтому лог сообщает `Compiling source ... failed for missing arguments: CREATOR`. Ошибка возникает на этапе компиляции вызова, ещё до попытки разрешить конкретный ID изготовителя. Лог не позволяет утверждать, что из-за неё перестаёт работать вся цепочка или весь мод; он подтверждает неисправность этих вариантов вызова.

Файл определения в сообщении — базовый `common/scripted_effects/00_agot_artifact_crowns_effects.txt`. Однако источник неполных вызовов — **AGOT+ и LOTD**, а не отсутствие персонажей в AGOT.

Проверены **52 вызова** восьми функций в эффективных `common/` и `events/`. В 40 аргумент присутствует, в 12 отсутствует. Все восемь действующих определений поставляет AGOT. [Все вызовы](all-effective-crown-calls.json), [определения](effective-crown-definitions.json), [12 текущих мест](current-crown-call-sites.json).

В AGOT+ это обработчики получения титула в `common/on_action/agot_on_actions/test_title_on_actions.txt`. Они прямо проверяют, что носитель канонической черты — **динамический персонаж, а не исторический `character:Targaryen_...`**. Затем создают корону и через день вызывают её экипировку. Следовательно, подмена динамического владельца фиксированным историческим персонажем противоречила бы условиям самого автора.

В LOTD это успешное нахождение артефакта в `events/decisions_events/rediscover_events.txt`. `this` — получатель находки. После создания сохраняются претензии Таргариенов и дальнейшая обработка артефакта. Функция претензий использует `scope:newly_created_artifact`, поэтому сохранение этого scope обязательно.

## Варианты решения CREATOR

**1. Добавить `CREATOR = this`.** Формально аргумент будет передан. Но создателем окажется новый король или нашедший корону персонаж. Это необоснованная запись об изготовлении. Не рекомендую.

**2. Взять кузнеца двора или создать ремесленника.** Так устроено настоящее изготовление в действующем событии заказа корон: оно заранее сохраняет `scope:smith`, а при отсутствии придворного кузнеца создаёт ремесленника. В анализируемых обработчиках этого контекста нет. Перенос такой логики означал бы добавление изготовления в наследование/нахождение и создание новых персонажей. Это изменение замысла, а не исправление пропущенной строки.

**3. Везде использовать `_historical_effect`.** Эти функции принимают только `OWNER`, но добавляют фиксированные даты, участников истории и иногда другие данные. Например, корона Бейлора получает создание 8161.6.9 с `character:Targaryen_82` и историю титула; обруч Висеньи — создание с `character:Targaryen_28` и `artifact_succession_title = title:c_kings_landing`. Часть записей добавляется через `agot_add_artifact_history`, который проверяет **`game_start_date`**, а не текущую дату кампании. Это существенно для длинных динамических прохождений. У LOTD уже есть отдельные исторические вызовы Эйгона I и Джейхейриса; их не нужно менять ради этих восьми ошибок. Универсальной заменой исторические функции не являются.

**4. Рекомендуемый вариант: создавать артефакт без указанного изготовителя.** В текущем AGOT есть точный структурный образец: `agot_create_artifact_crown_of_hugor_effect` в том же файле, строка 4032. Он принимает `OWNER`, создаёт корону с качеством, шаблоном и модификатором, сохраняет `newly_created_artifact`, устанавливает маркеры и не задаёт `creator`. Это опора на действующий код AGOT, а не предположение, что обязательный аргумент можно просто пропустить у прежней функции.

Для каждой нужной короны предлагается отдельное определение на основе её нынешней функции AGOT. Из тела убираются только:

```text
$CREATOR$ = { save_scope_as = creator }
creator = scope:creator
```

Сохраняются `OWNER`, редкость, качество, стоимость, название, описание, модель, шаблон, модификатор, `decaying = no`, `newly_created_artifact` и все маркеры. Проверка AST восьми проектов подтвердила: иных изменений внутри функций нет; дополнительных ссылок на `creator` не осталось. В соответствующих восьми шаблонах прямых ссылок на изготовителя тоже нет. Сведения об изготовителе намеренно не задаются; внешний вид вкладки истории и выполнение события всё равно потребуют проверки в игре.

Меняются только 12 проблемных вызовов. Общие функции AGOT и остальные 40 вызовов остаются прежними. Чтобы сохранить независимость двух наших исправлений, семь помощников AGOT+ следует размещать в **AGOT_PLUS_FIX** со своим префиксом, пять помощников LOTD — в **AGOT_SUBMODS_FIX** с другим. Четыре общих вида корон получат отдельные имена функций в двух патчах, без одинаковых глобальных ID и без зависимости AGOT_PLUS_FIX от объединённого патча.

[Проект тел восьми функций](PROPOSAL-ONLY-crown-effects.txt) имеет демонстрационные имена `review_...` и лежит только в отчёте; в игру не подключён. [Исходные обычные и исторические определения](crown-effect-excerpts.txt), [сравнение аргументов и полей](crown-functions.json).

## COW: ройнарский бонус — теперь точное исправление

Проблема находится в `agot_plankytown_01`: два блока дают +10 владельцу здания и +5 через `county_holder_character_modifier` со старым именем `rhoynish_religion_opinion`.

В **текущем AGOT у этого же `agot_plankytown_01`** находятся те же два блока с `the_mother_religion_opinion = 10` и `= 5`: `common/buildings/00_agot_special_buildings_westeros.txt:598,605`. После замены имени **оба блока целиком совпадают с базовым AGOT**, включая остальные бонусы. Это более сильное доказательство, чем просто похожее имя религии.

Дополнительная проверка: `the_mother_religion` определена в `common/religion/religion_types/00_agot_the_mother.txt`; формат одноимённого бонуса есть в `common/modifier_definition_formats/00_religion_definitions.txt`. Это мнение религии, а не культуры и не только одной конфессии `mother_rhoyne`. Масштаб и величину бонуса сохраняем по действующему зданию AGOT. [Проверка эквивалентности](plankytown-modern-equivalence.json).

## COW: шахты Харлоу

В `harlaw_building_check_on_actions` после завершения строительства проверяются провинция **2819**, замковое владение и отсутствие специального слота. Для персонажа династии Харлоу создаётся слот `agot_ten_towers_01`, для другой династии — `harlaw_mines_01`.

В эффективных определениях зданий шахт Харлоу нет. Их названия и описания действительно остались в локализации AGOT; наличие текста не возвращает объект здания, его уровни, требования и бонусы. В старом закомментированном коде COW также сохранились обращения к четырём уровням шахт и замена их Десятью Башнями. Это подтверждает существование прежней развилки, но не даёт полного определения шахт.

Современная история `history/provinces/00_k_the_iron_islands_prov.txt:803` задаёт провинции 2819 специальный слот **`agot_ten_towers_01`**, а с **8178.1.1** — построенные Десять Башен и `castle_05`. До этой даты история титула удаляет владение. Поэтому объявлять ветвь проверки пустого слота абсолютно недостижимой нельзя. В текущем здании COW Десять Башен имеют проверку баронства и обычные требования строительства, но не ограничение по династии.

**Минимальный вариант:** закомментировать целиком только второй `if`, устанавливающий недоступные шахты. Положительная ветвь Харлоу, история провинции, модель и бонусы Десяти Башен сохраняются. В редком состоянии «нет слота, владелец не Харлоу» дополнительный слот этим обработчиком создаваться не будет; сейчас там вызывается отсутствующий объект. Исправление не восстанавливает шахты.

**Альтернатива для последующего решения:** при отсутствии слота устанавливать современные Десять Башен независимо от династии. Это согласуется с текущим объектом AGOT, но меняет исходную развилку автора, поэтому не включено в минимальный проект. Перенос шахт Оркмонта, другого региона или собственная выдуманная цепочка уровней ещё сильнее меняли бы содержание.

## COW: отсутствующее событие agot_cities.5000

Найдены три действующих вызова в `on_complete`:

- `planky_town_special`;
- `agot_castamere_03`;
- `24castamere_03`.

Все вызывают событие на `barony.holder`. Каждая ссылка даёт две диагностические записи, итого шесть. Определения `agot_cities.5000` в действующих событиях нет. В установленном COW присутствует единственный файл событий `agotcities_castamere_ruins.txt`, с другим namespace — `agot_castamere_ruins`.

**Это не повод переименовать вызов в `agot_castamere_ruins.1000`.** Последнее событие уже вызывается отдельно при восстановлении Кастамере. Оно ищет провинцию с `ruin_holding`, `medium_ruin_03` и `agot_castamere_ruins_02`, затем меняет владение на замок, ставит `24castamere_01` и `castle_02`, даёт престиж. Для достроенного третьего уровня или Дощатого Города это другой контекст; поиск подходящих руин может не дать нужного scope. Подмена могла бы вмешаться в другое владение или не сработать.

Нынешняя [страница автора COW](https://steamcommunity.com/sharedfiles/filedetails/?id=2971198450) описывает восстановление Кастамере через улучшения руин и специального здания. Это согласуется с сохранённой отдельной цепочкой. Страница не документирует тело `agot_cities.5000`. В просмотренных [заметках обновлений](https://steamcommunity.com/sharedfiles/filedetails/changelog/2971198450) и их [второй](https://steamcommunity.com/sharedfiles/filedetails/changelog/2971198450?p=2)/[третьей](https://steamcommunity.com/sharedfiles/filedetails/changelog/2971198450?p=3) страницах доступные записи не содержат объяснения удаления этого события. Исходное тело не найдено; по одному номеру нельзя доказать, что событие было лишь уведомлением, выдавало награду или меняло владение. Жалобы пользователей на похожие цепочки не использованы как доказательство содержания именно `.5000`.

**Безопасный проект:** закомментировать три соответствующих `on_complete` целиком. Сами здания, уровни улучшений, параметры, модели и действующее `agot_castamere_ruins.1000` остаются. Это прекращает вызов отсутствующего события, но не обещает вернуть неизвестную награду или иное его действие. [Три вызывающих здания с определениями](cow-missing-event-calls.json).
