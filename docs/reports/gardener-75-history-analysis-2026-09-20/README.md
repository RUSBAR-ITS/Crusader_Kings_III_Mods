# Gardener_75: назначение и историческая совместимость

Исследование от 20 сентября 2026 года. Игровые файлы не изменялись. Проверены установленный AGOT, Crowns of Westeros, Submod Core, состав эффективных файлов текущего набора модов и публичные исторические исходники.

**Последующее применение, 20 сентября:** после дополнительной проверки справочников пользователь согласовал сохранение описаний без подстановки исторического владельца. В `AGOT_SUBMODS_FIX` закомментированы две записи первоначального изготовления; остальные эффекты и текущие владельцы корон сохранены. Прежние 27 файлов патча не изменились, добавлена одна копия файла эффектов Crowns. Сборщик воспроизводит 28 файлов, 170 статических проверок пройдены. [Результат сверки](application-validation.json). Указания ниже об отсутствии игровых изменений относятся к стадии исследования; новый запуск игры после применения не проверен.

**Вывод:** замысел Crowns установлен: `Gardener_75` обозначает в его описаниях Мерина IV Гарденера, первоначального получателя двух корон, позднее принадлежавших Мерну IX. Ссылка опирается на старую историю титула. Современный эквивалент этого персонажа не установлен. Поиск не дал основания заменять его Мерном IV, Мерном IX, нынешним сыном Джона III или сводным персонажем, обозначающим несколько поколений.

## Для чего используется ссылка

В `common/scripted_effects/00_ntc_scripted_effects_crowns.txt` два эффекта:

- `create_artifact_gardener_war_crown_effect`, строка 4460;
- `create_artifact_gardener_peace_crown_effect`, строка 4509.

Оба содержат одинаковую запись происхождения:

```text
history = {
    type = created
    date = 7692.1.8
    recipient = character:Gardener_75 # Meryn IV Gardener
    location = province:3237
}
```

Провинция `3237` по текущему `01_agot_landed_titles.txt` — `b_highgarden`, Хайгарден. Эта часть ссылки корректна.

`recipient` находится **внутри истории артефакта**: это исторический получатель при его создании. Владелец создаваемого в кампании предмета задаётся отдельно через `$OWNER$`, который сохраняется в `scope:owner`. В этих двух эффектах нет параметра `$CREATOR$`; смешивать эту ошибку с ранее разобранными вызовами `CREATOR` нельзя.

Также отдельно задаются визуальная модель, шаблон, модификатор свойств, маркер конкретной короны, историческая уникальность, `artifact_succession_title = title:c_highgarden`, дальнейшая история по титулу Простора и претензии домов династии Гарденеров.

Найдены следующие прямые пути вызова:

| Путь | Что происходит |
|---|---|
| `ntc_tyrell_crown_shattered_spawn.1` | Обе короны создаются у держателя `e_the_reach`, если включено `show_dynamic_crowns_enabled`. Вызовы этого стартового эффекта есть в сценариях раздробления мира на мелкие королевства и королевства. |
| `ntc_crown_storage_decision` | Держатель Королевской Гавани может получить мирную корону вместе с другими историческими коронами. У решения есть собственные условия, включая дату старта, престиж, антиквара и отсутствие войны. |
| Отключённое отладочное решение | Ещё два вызова уже закомментированы самим Crowns. |

Это рабочее содержимое мода. Предлагалось отключать только две записи происхождения, **не эффекты создания корон**.

## Что говорит локализация автора

Проверены три ключа в установленном `localization/replace/english/ntc_artifacts_l_english.yml`, строки 51, 54 и 57. Ниже пересказ авторских описаний, а не утверждение об установленном книжном каноне.

1. Прежняя корона Золотой Руки была потеряна в море вместе с Джоном III Гарденером. После этого его сын Мерин IV заказал себе новую корону.
2. Военная корона названа именем последнего владельца — Мерна IX, но впервые изготовлена для Мерина IV. Описываемый предмет назван репликой: оригинал погиб на Пламенном Поле.
3. Мирная корона тоже изготовлена для Мерина IV. По описанию Crowns она пережила Пламенное Поле и попала к Эйгону I.

Таким образом, имя Мерина IV присутствует не только в комментарии программиста. Оно связано с общей историей трёх предметов. Замена первоначального получателя на Мерна IX противоречила бы этому рассказу.

Книжная традиция двух корон — цветы и лозы в мирное время, бронзовые, позднее железные шипы в военное — приведена в [справочнике по дому Гарденеров](https://awoiaf.westeros.org/index.php/House_Gardener) со ссылкой на «Мир Льда и Пламени». Но в проверенной статье нет подтверждения истории Мерина IV и кораблекрушения Джона III. Поэтому эту дополнительную биографию следует считать подтверждённым замыслом Crowns, **без приписывания её Мартину**. При дополнительной проверке 7kingdoms удалось прочитать прямым HTTP-запросом; сопоставление Мерна VI, Мерина III и истории корон приведено в [дополнении по двум справочникам](canon-followup.md).

## Что находится в текущем AGOT

Проверено 105 определений `Gardener_*` в `00_agot_char_reach_ancestors.txt`. Этот файл и `agot_e_the_reach.txt` в эффективном наборе принадлежат самому AGOT: их не вытеснил наш патч или DI. Поиск `Gardener_75` по установленным текстовым файлам Workshop нашёл только две активные ссылки Crowns и закомментированные ссылки Core; определения нет.

Все пять нынешних персонажей с именем `Meryn`:

| ID | Кто это | Даты жизни в файле |
|---|---|---|
| `Gardener_9` | Мерин I | 2081–2140 |
| `Gardener_14` | Мерин II | 2184–2250 |
| `Gardener_45` | Мерин III | 6220–6289 |
| `Gardener_85` | Старший сын Мерна VIII, погибший в несчастном случае | 7873–7887 |
| `Gardener_104` | Другой Мерин, погибший на Пламенном Поле | 7986–8000 |

Ни один из них не жил в `7692`. Мерн IV (`Gardener_47`, 6830–6881) имеет другое имя и тоже не подходит по датам.

Джон III сейчас определён как `Gardener_73`, жил в 7282–7324. Его сын и преемник — Грейдон I (`Gardener_61`), затем следуют Персеон III и Гвейн VI. Это другая последовательность, чем в рассказе Crowns. Между Гвейном VI и Мерном VII есть сводный персонаж `Gardener_28`, `Line_of_Gwayne`, с чертой `line_of_char`, покрывающий 7399–7780. Он обозначает линию потомков, а не конкретного Мерина IV. Назначать его историческим заказчиком корон было бы новой выдумкой.

## Решение с минимальными предположениями

Рекомендация остаётся **закомментировать два полных блока `history = { type = created ... }`**, но теперь основание точнее: замысел автора понятен, а его конкретный исторический адресат не представлен в текущей родословной.

При этом сохранить:

- весь код создания обеих корон и его вызовы;
- свойства, модели, текущего получателя, правила наследования и претензии;
- остальную существующую историю предметов;
- авторские описания с историей Мерина IV;
- исходный текст двух записей в комментариях с пояснением об отсутствии совместимого персонажа.

Потеря ограничивается двумя отдельными пунктами истории о первоначальном изготовлении: по одному на корону. Утверждать, что исчезнет вся история предметов или сами короны, нет оснований. Но итоговое поведение движка после изменения всё равно следует проверять следующим запуском, это исследование не является игровым тестом.

Почему не другие варианты:

- **Не заменять на нынешнего владельца:** он может родиться намного позже даты `7692.1.8`.
- **Не подставлять последнего владельца Мерна IX:** это смешает первоначальное изготовление с позднейшим владением и противоречит описаниям.
- **Не создавать нового исторического персонажа:** его исходная биография не восстановлена; нынешняя родословная уже другая. Для исправления двух ссылок пришлось бы самостоятельно выбирать родителей, даты, место в династии и титульной истории.
- **Не удалять только `recipient`:** стандартная локализация CK3 для записи `created` напрямую обращается к `HISTORY_ENTRY.GetRecipient`. Для неизвестного изготовителя там есть отдельная обработка, для неизвестного получателя — нет. Такая частичная правка не подтверждена как корректная.

Дополнительное наблюдение: у военной короны история по титулу добавляется с `7980.1.8`, у мирной — с `7692.1.8`. Различие было уже в публичной версии 2024 года. Само по себе оно не доказывает ошибку; в рамках исправления `Gardener_75` эти даты менять не предлагается.

[source-evidence.json](source-evidence.json) содержит SHA-256 локальных файлов, URL и коммиты исторических файлов, а также выдержки с номерами строк. [current-gardeners.json](current-gardeners.json) — проверенные определения текущих Гарденеров. [summary.json](summary.json) — краткий результат.

Сбор только читает игровые источники и пишет материалы в этот каталог:

```powershell
$env:PYTHONDONTWRITEBYTECODE='1'
python docs/reports/gardener-75-history-analysis-2026-09-20/Collect.py
```

Не установлен точный коммит удаления/переработки `Gardener_75` в основном AGOT и не восстановлено старое определение его биографии. Публичная история Core и старый титульный файл Bookmarked сужают вопрос, но не заменяют отсутствующее определение персонажа.
