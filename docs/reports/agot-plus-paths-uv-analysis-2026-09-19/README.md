# AGOT+: длинные пути и UV моделей — исследование

Дата: 19.09.2026. Основа: сохранённый запуск ревизии 12, CK3 1.19.0.6, AGOT 0.5.2.1, прежний порядок 32 модов.

**Статус: исследование; игровые файлы, дескрипторы, реестр и плейсет не изменены.** Все 84 файла установленного FIX совпадают с манифестом ревизии 12. Предлагаемые изменения моделей проверены только в памяти; готовые модели не установлены и игра не запускалась.

## 1. Длинные пути: сильное подтверждение, но ещё не трассировка CK3

Проверены все 84 игровых файла FIX через `GetFileAttributesW` и `CreateFileW`, с открытием только для чтения. Обычным абсолютным путём открываются 81 файл; **ровно три** остальных возвращают Windows error 3, `ERROR_PATH_NOT_FOUND`. С префиксом `\\?\` открываются все 84. Полученные первые байты сопоставлены с реальными файлами.

Это те же три файла, для которых после прошлого запуска сохранились целевые ошибки:

| Исправление | Длина пути FIX | Обычное открытие | Длина пути оригинала Workshop | Открытие оригинала | Осталось сообщений |
|---|---:|---|---:|---|---:|
| Нога железнорождённых, `.asset` — контроль | 246 | Успех | 173 | Успех | 0 |
| Мужской королевский плащ Ланнистеров, `.asset` | 278 | Ошибка 3 | 205 | Успех | 1 |
| Женский королевский плащ Ланнистеров, `.asset` | 282 | Ошибка 3 | 209 | Успех | 1 |
| Женская высокая броня Ланнистеров, `.mesh` | 283 | Ошибка 3 | 210 | Успех | 18 |

Содержимое всех четырёх файлов соответствует ранее проверенной сборке. Оригиналы Workshop доступны и имеют существенно более короткие пути. Поэтому сохранение исходных диагностик согласуется с тем, что длинные перекрытия не были прочитаны движком.

Дополнительные факты:

- `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled = 0`.
- Встроенный ресурс manifest ID 1 установленного `ck3.exe` не содержит `longPathAware`. Внешний `ck3.exe.manifest` также не содержит этого элемента. EXE загружался только как ресурс данных, без исполнения.
- Длины измерены для полного физического пути, включая корень репозитория, без завершающего NUL.
- Максимальная длина текущего FIX — 283; три недоступных обычному API файла являются единственными его игровыми файлами с длиной не менее 260.

**Что доказано:** ограничение обычного Win32-доступа воспроизводится на этих конкретных файлах; сами файлы существуют и читаются расширенным путём.

**Что пока является выводом:** именно это мешает CK3 использовать три перекрытия. Проба выполнена из Python, а движок может использовать собственную файловую обёртку. Монтирование мода в `debug.log` и корректные хеши не подтверждают открытие каждого ресурса. Для окончательного доказательства нужен запуск той же сборки с коротким путём либо трассировка файловых операций CK3.

Доказательства: [path-probes.json](path-probes.json), [встроенный manifest CK3](ck3-embedded-manifest-1.xml).

### Что удалось найти в сети

1. Microsoft документирует `MAX_PATH = 260`, расширенные пути и необходимость одновременно включить системную настройку и объявить поддержку в manifest приложения. Поэтому одно включение реестра нельзя считать достаточным решением для CK3. [Microsoft: Maximum Path Length Limitation](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation).
2. В исходниках **CK3 Playset Preserver** есть специальная обработка отказа копирования модов при пути от 260 символов: программа предлагает укоротить имя каталога и повторяет копирование. Это прямой пример аналогичной проблемы с файлами модов CK3, но на этапе работы внешней утилиты. [Исходный код CK3 Playset Preserver](https://github.com/nullheimer/CK3-Playset-Preserver/blob/main/CK3_PP.py).
3. Пользователь **Elder Kings** описал ошибку `0x80010135` при распаковке `.mesh` головного убора в длинный путь Documents/OneDrive. В последнем дополнении он сообщил об успешной распаковке сначала в другой каталог и последующем запуске мода. Это свидетельство установки, а не подтверждение того, как VFS CK3 обрабатывает длинное перекрытие. [Первичный рассказ пользователя, 17.04.2023](https://www.reddit.com/r/ElderKings/comments/12p686f).

Публичного воспроизведения **точно нашего** случая — три корректных перекрытия AGOT+ молча не применяются из-за длинного корня — не найдено. Наиболее сильное свидетельство здесь даёт локальный эксперимент, а не похожие обсуждения.

### Предлагаемое решение путей

Предпочтителен короткий путь подключения FIX, например `D:\CK3Mods\AGOT_PLUS_FIX`. Для сохранения одного рабочего экземпляра можно использовать junction на существующий каталог репозитория. Это предложение, junction ещё не создана. После создания необходимо проверить обычное открытие всех файлов именно по короткому пути и убедиться по следующему запуску, что CK3 использует его. Если движок разворачивает ссылку обратно в длинный путь и проблема остаётся, запасной вариант — физическая сборка в короткий каталог с проверкой хешей.

Важно учесть сборочные инструменты: `Build-AGOTPlusFix.ps1:93` сейчас заново записывает длинный `$modRoot` в внешний дескриптор, а `Test-AGOTPlusFix.ps1` требует буквального совпадения пути с корнем. При реализации нужен согласованный путь подключения для генератора и проверки, а не разовая ручная правка, которую затрёт следующая сборка. Проверка должна подтверждать, что короткий путь ведёт к той же сборке. Идентификатор дескриптора и порядок модов можно сохранить.

Укорачивать внутренние имена моделей и переписывать их ссылки для этого не требуется. Один лишь префикс `\\?\` в дескрипторе не предлагается: поддержка этого синтаксиса лаунчером и VFS отдельно не проверена.

## 2. UV: две разные причины в одной категории

В прежних **75 сообщениях / 48 файлах** находятся два вида диагностик. Отнесение всей категории к лишним каналам было бы неверным.

| Диагностика | Сообщений | Файлов | Результат разбора |
|---|---:|---:|---|
| Больше трёх UV-каналов, `pdxassetutil.cpp:2002` | 39 | 37 | 39 частей моделей содержат `u0`, `u1`, `u2`, `u3` |
| Нет треугольника с площадью для texture streaming, `pdxassetutil.cpp:556` | 36 | 11 | 35 отдельных каналов сведены в одну точку; одна модель зарегистрирована дважды |

Все 48 эффективных исходников принадлежат AGOT+. Их контрольные суммы закреплены. Двоичная структура проверена собственным индексатором токенов и отдельно существующим читателем `pdx_data.py` из io_pdx_mesh. Это не восстановление файлов по текстовому представлению: исходные байты сохраняются.

### Четвёртый канал

В 39 частях моделей четвёртый канал — `u3`. Число этих частей точно совпадает с количеством соответствующих сообщений по каждому файлу.

- В **31 случае** четвёртый канал побайтово совпадает хотя бы с одним из первых трёх.
- В **8 случаях** он отличается: мужские и женские плащ, броня, шлем и ноги золотых плащей. Отличие данных само по себе не означает, что они используются.
- В установленном входном формате шейдера `cw/pdxmesh.fxh` и `pdxmesh_buffers.fxh` доступны UV0–UV2. UV3 в этот вход не передаётся. В выбранных материалах нет основания переносить четвёртый канал поверх первых трёх.

**Предложение:** удалить только двоичное свойство `u3` в этих 39 частях. Не менять порядок вершин, треугольники, тангенты, привязку к костям или текстуры. Первые три канала сохраняются, за исключением отдельно обоснованных неиспользуемых каналов ниже.

В универсальном экспортёре io_pdx_mesh действительно предусмотрено четыре UV-набора (`PDX_MAXUVSETS = 4`, структуры `u0`–`u3`). Поэтому файл может быть допустим для инструмента экспорта и при этом превышать лимит установленного CK3. Это объясняет техническую возможность появления таких файлов, **но не доказывает, каким инструментом их создавал автор AGOT+**. [Константы экспортёра](https://github.com/ross-g/io_pdx_mesh/blob/master/library.py), [экспорт данных Blender](https://github.com/ross-g/io_pdx_mesh/blob/master/pdx_blender/blender_import_export.py).

По одной фразе лога нельзя установить, отбрасывает ли движок только лишний канал, все UV или более крупную часть загрузки. Вывод об отсутствии входа UV3 подтверждается локальными шейдерами; утверждение, что текущая модель целиком не отображается, не делается.

### Развёртки с нулевой площадью

В 35 каналах, объясняющих 36 сообщений, все UV-координаты одинаковы: `(0, 1)` либо примерно `(0.0000305, 0.0000305)`. Треугольники модели имеют одну и ту же UV-точку на всех вершинах, поэтому площадь в текстурных координатах равна нулю.

Распределение сообщений:

- Штормовой Предел — 21.
- Красный замок — 1.
- Мужской и женский плащи Ночного Дозора — по 3.
- Женская броня Мандерли — 2: одна вырожденная часть, два определения pdxmesh.
- Женское траурное платье Западных земель, женские туфли, мужская кожаная броня Дозора, туника Тайвина, кожаные сапоги № 2 и ноги Дозора — по 1.

Исследованы все эффективные `.asset`, ссылающиеся на рассматриваемые модели, и настройки каждого проблемного подмеша. Используются только четыре эффекта: `court`, `court_alpha_to_coverage`, `portrait_attachment`, `portrait_attachment_alpha_to_coverage`. Оба эффективных файла шейдеров поставляет AGOT.

В этих вариантах текстуры берутся по UV0. Ветки для дополнительных узоров/гербов, использующие UV1/UV2, не включены; дополнительных переопределений в соответствующих meshsettings нет. Поэтому можно убрать проблемные **неиспользуемые** каналы. Основная развёртка UV0 остаётся прежней; подставлять её вместо вырожденной и придумывать новое размещение текстуры не нужно.

Дополнительно обнаружены **шесть не отмеченных отдельными сообщениями каналов** у мужских и женских плаща, брони и шлема золотых плащей. Там координаты не совпадают в одной точке, но все треугольники всё равно имеют нулевую UV-площадь. Материалы также не используют эти каналы. Их стоит включить в ту же обработку; после устранения превышения числа каналов они потенциально могут проявиться отдельной диагностикой. Отсутствие сообщений сейчас не приписывается доказанному внутреннему порядку проверок CK3.

Удалять предлагается непрерывный хвост каналов от первого неиспользуемого вырожденного слота. Поэтому дополнительно убираются **8 неиспользуемых UV2**: два у меха плащей Дозора и шесть у перечисленных моделей золотых плащей. Это исключает пропуск `u1` при оставленном `u2`. Работающие UV2 у материалов с гербами/вариациями сохраняются.

Доказательства: [collapsed-uv.json](collapsed-uv.json), [определения моделей и материалов](mesh-registrations.json), [фрагменты эффективных шейдеров](shader-evidence.txt).

## 3. Проверенный объём предлагаемой правки

В памяти подготовлен и проверен вариант для 48 моделей:

| Удаляемые UV-свойства | Количество |
|---|---:|
| Неподдерживаемые четвёртые каналы | 39 |
| Неиспользуемые каналы с нулевой площадью: 35 из лога + 6 дополнительных | 41 |
| Неиспользуемые последующие каналы, чтобы не оставлять пропуск индекса | 8 |
| **Всего** | **88** |

Удаляется 3 560 448 байт из 66 464 741 байта исходных моделей. Это технический объём данных, не сокращение геометрии.

Проверено:

- Каждый исходный и оставшийся двоичный токен корректно разбирается.
- Все неудаляемые свойства и заголовки объектов побайтово совпадают, включая геометрию, номера/порядок вершин и треугольников, нормали, тангенты, материалы, скелет, веса и оставшиеся UV.
- Во всех частях остаётся не более трёх каналов, с последовательными индексами.
- В каждом оставшемся UV-канале есть треугольник с ненулевой площадью.
- Файлы деформаций, модели других модов и определения шейдеров не изменяются.
- Все 84 действующих файла FIX сохраняют хеши ревизии 12.

Это сильная структурная проверка, а не проверка рендера или точного порога расчёта texture streaming внутри закрытого движка. Следующий игровой запуск нужен для проверки исчезновения сообщений; визуальное сравнение всех портретов не требуется для установления перечисленных структурных фактов.

Отдельно проверены 309 ссылок на 300 файлов деформаций этих моделей. Исходные количества вершин и наборы UV совпадают с базовыми моделями. `cw/pdxmesh_blendshapes.fxh` применяет смещения позиций, нормалей и тангентов по номерам вершин; UV в расчёте деформации не участвуют. Поэтому изменение только неиспользуемых UV не затрагивает сам расчёт. Однако наличие дополнительных проверок соответствия UV в закрытом загрузчике этим не исключено: при следующем запуске нужно также проверить отсутствие **новых** ошибок blendshape. Если загрузчик требует одинаковый набор UV, запасное решение — синхронно удалить те же неиспользуемые свойства в соответствующих деформациях, сохраняя их геометрию. Пока эти 300 файлов менять не предлагается. [Проверка деформаций](blendshape-layout-summary.json).

[Точные диапазоны байтов и хеши предложений](uv-proposal.json), [результат проверки](proposal-validation.json), [все каналы](uv-channels.csv).

## 4. Порядок последующей реализации

1. Организовать короткий путь подключения FIX, согласовать генерацию дескриптора и её проверку. Проверить обычное чтение всех файлов через этот путь.
2. Включить точечные двоичные изменения 48 моделей в воспроизводимую сборку с закреплёнными хешами исходников. **У 9 из этих моделей путь в нынешнем корне FIX достиг бы 260 символов; максимум — 288.** Поэтому сначала требуется решить вопрос корня. Для предложенного короткого корня максимальный путь этих моделей — 178 символов.
3. Проверить следующий запуск: 18 сообщений деформаций Ланнистеров, 2 дубля плащей, 39 превышений числа UV и 36 ошибок UV-площади. Дополнительно проверить, что не появились сообщения о шести найденных каналах золотых плащей и новые ошибки соответствия деформаций.

Это потенциально закрывает **95 из 135** оставшихся сообщений, связанных с AGOT+. Ожидаемый остаток — 40 при отсутствии новых диагностик; это прогноз, не результат уже состоявшейся проверки. Четыре дубля DDS и остальные категории этим планом не устраняются.

Для более строгого доказательства причины путей можно сделать отдельный контрольный запуск после шага 1, до изменения UV. Обязательным условием исследования такой дополнительный запуск не является.

Запускать по порядку из корня репозитория, пока источники и ревизия 12 неизменны:

```powershell
python docs/reports/agot-plus-paths-uv-analysis-2026-09-19/analyze.py
python docs/reports/agot-plus-paths-uv-analysis-2026-09-19/inspect-flat-uv.py
python docs/reports/agot-plus-paths-uv-analysis-2026-09-19/verify-proposal.py
python docs/reports/agot-plus-paths-uv-analysis-2026-09-19/check-blendshape-layout.py
```

Скрипты пишут только доказательства в этот каталог. Не запускают игру, не меняют настройки и не устанавливают модели. [Хеши источников](source-pins.json), [состояние runtime](validation.json).
