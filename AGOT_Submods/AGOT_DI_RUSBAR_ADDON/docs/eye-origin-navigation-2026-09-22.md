# Выбор культуры и веры в «Оке» — 22 сентября 2026

Первоначальное требование пользователя: группировка и оформление как в DI, с сохранением текстового поиска. После исследования пользователь согласовал на этом этапе **группы DI с удалением сломанного поля поиска**. Первый пользовательский запуск выявил заглушку вместо списка; исправление структуры GUI описано ниже. Исправленная отрисовка ещё не проверена в CK3.

## Подтверждённая причина поломки поиска

В текущем `error.log` движок сообщает:

```text
Function 'Set' expected 2 arguments, got 1
GetVariableSystem.Set('agot_di_rusbar_culture_search')
Failed parsing data statement ... for property 'ontextedited'
```

Для веры зарегистрирована та же ошибка. Поле ввода не передавало строку в переменную. Кроме того, старый `EqualTo_string` сравнивал полное название с учётом регистра и не реализовывал поиск по фрагменту.

В установленном DI эти списки вообще не имеют текстового поиска. В изученных GUI игры обработчики редактирования привязаны к штатным объектам окон. Рабочая универсальная привязка произвольного введённого текста к нашему фильтру не найдена. Это граница проведённого исследования, а не доказательство невозможности такой функции в CK3.

По последнему согласованию поля поиска, их состояния и недействительные `ontextedited` удалены. Возвращение рабочего текстового поиска отложено; исправленным поиск не считается.

## Реализованные группы

- Культуры сгруппированы по наследию. Каждый заголовок раскрывает текущий `CulturePillar.GetCulturesWithPillar`.
- Конфессии сгруппированы по религиям через `Religion.GetFaiths`, с иконками веры. Пустые религиозные группы скрыты.
- Внешний порядок списков и вложенных элементов следует игровым перечислениям, как в DI; отдельная алфавитная сортировка не добавлена.
- Текущий выбор отмечен, его группа раскрывается при открытии панели. Щелчок выбирает происхождение для будущего придворного и возвращает к должностям.
- Унаследованы общие подсказки культуры/веры, но не действия редактора правителя и не действия смены культуры/веры существующим персонажам из DI.
- Представители наследий и религии хранятся в списках игрока; они очищаются перед повторным открытием и при закрытии. Динамические культуры и конфессии берутся из состояния кампании.
- Имена состояния раскрытых групп имеют собственные префиксы «Ока». Глобальные списки и настройки DI не меняются.

## Проверка

Первоначальные 45 проверок не выявили проблему отрисовки. Они проверяли структуру скриптов, ссылки GUI, локализацию, очистку списков и границу между выбором происхождения и изменением персонажа, но не раскрытие унаследованных GUI-блоков движком. После обнаружения заглушки добавлена отдельная проверка места переопределения содержимого. Игра агентом не запускалась, лаунчер не менялся.

При следующем пользовательском запуске: проверить раскрытие обеих панелей, выбор другой культуры/веры, отметку текущего выбора, возврат к должностям и повторное открытие. Отдельно проверить появление новой гибридной культуры и новой конфессии в соответствующих группах. Ошибки одноаргументного `Set` в поиске больше не должны возникать; сам поиск ещё не готов.

## Исправление фиолетовой заглушки после пользовательского запуска

На снимке вместо обеих панелей появился квадрат. Его источник установлен по коду игры: штатный `scrollbox` в `game/gui/shared/lists.gui` содержит `debug_square = {}` в блоке `scrollbox_content`. Сам `debug_square` в `game/gui/debug/placeholder_types_templates.gui` — иконка размером 100 × 100 с текстурой `pink_square_chill.png`; её вид и масштаб соответствуют снимку.

Наши типы наследовались прямо от `scrollbox`, а `blockoverride "scrollbox_content"` находился в определении производного типа. В пользовательском запуске это оставило исходную заглушку. Теперь обе панели повторяют структуру DI: тип на основе `vbox`, вложенный экземпляр `scrollbox`, переопределение содержимого внутри этого экземпляра. Списки, группировка и действия выбора сохранены. Не вводятся новые изображения для маскировки заглушки.

В свежем логе также выявлены четыре сообщения об устаревших списках `agot_di_rusbar_eye_cultures`/`agot_di_rusbar_eye_faiths`: по два прохода проверки для двух имён. Удалены их оставшиеся вызовы очистки. Действующие списки наследий и религий продолжают очищаться; существующие старые списки в сохранениях больше нигде не читаются.
